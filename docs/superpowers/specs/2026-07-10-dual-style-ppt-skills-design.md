## 1. 背景与问题

本项目要把同一份 47 页医学原稿分别改写为风格1和风格2，并最终交付两份对象级可编辑 PPTX。两份输出不仅视觉不同，内容组织方式也必须分别贴近两个参考文件夹。

目标流水线为：

1. 提取并核对原稿事实。
2. 按目标风格改写内容。
3. 将改写内容写入中间 PPT。
4. 逐页渲染成图片，并参考对应风格进行视觉重绘。
5. 将重绘图片回建为对象级可编辑 PPT。
6. 校准文字、事实和版式，交付最终文件。

当前主要阻塞点在内容改写，而不是视觉生成或可编辑回建。现有实验曾采用两种不同处理方式：

- 风格1实验曾采用压缩页数并重组章节的方式。
- 风格2实验曾采用保留原结构并局部替换标题和正文的方式。

这些页数和处理方式只是用于定位问题的历史观察，不是新流程的输入约束，也不是未来输出必须遵守的页数。新流程应先完成参考风格拆解和内容规划，再动态决定每种风格的页面数量、研究顺序与拆分方式。

当前问题还包括：
- 两条路线没有共享的事实底稿，也没有统一的内容改写边界。
- 风格1参考文件中包含草稿页、占位表述和未完成指令，不能全部作为可信范本。
- 当前提取与页面分类存在误判，可能污染后续改写。
- 内容稿没有逐条绑定原稿页码、数字、图表和引用，难以自动发现漏项或过度解读。

## 2. 目标与非目标

### 2.1 目标

交付两个独立安装和调用的 Skill：

1. 风格1医学会议长报告 Skill。
2. 风格2医学速递简报 Skill。

两个 Skill 共享同一套事实提取、事实验证、运行清单和可编辑回建能力，但分别拥有独立的内容策略、视觉画像、页面结构和验收样例。

每次运行应产出：

- 经验证的事实底稿。
- 风格专属逐页内容稿。
- 内容修改后的中间 PPTX。
- 逐页视觉稿和预览图。
- 对象级可编辑最终 PPTX。
- 内容、视觉和编辑性验证报告。

### 2.2 非目标

- 本阶段不做网页上传产品或桌面应用。
- 不把两个风格合并为一个带参数的通用 Skill。
- 不追求无需审核的全自动医学内容生成。
- 不让模型补充原稿中不存在的医学事实或外部研究结论。
- 不覆盖或修改用户原始 PPTX。
- 新流程验证通过前不删除历史实验文件。

## 3. 方案选择

### 3.1 可选方案

#### 方案 A：两个完全独立的 Skill

每个 Skill 独立完成提取、改写、视觉生成和回建。

优点是入口清楚；缺点是事实提取与验证代码重复，同一项研究可能被两套 Skill 解释成不同事实。

#### 方案 B：一个通用 Skill 加风格参数

所有流程集中在一个 Skill，调用时指定 `style1` 或 `style2`。

优点是文件数量少；缺点是内容规则和视觉规则容易互相污染，长期会形成大量条件分支，难以独立迭代和验收。

#### 方案 C：两个 Skill 加共享事实底座

两个 Skill 保持独立入口和独立风格策略，共用事实底稿、验证器、运行目录协议和可编辑回建接口。

该方案在风格隔离、事实一致性和代码复用之间最平衡，因此确定采用方案 C。

## 4. 总体架构

系统分为共享核心、风格适配层和外部回建能力三部分。

```text
原始 PPTX
  -> Source Extractor
  -> Evidence Ledger
       -> Style1 Content Adapter -> Style1 Native Draft -> Style1 Image Redesign
       -> Style2 Content Adapter -> Style2 Native Draft -> Style2 Image Redesign
  -> image-to-editable-ppt
  -> Text Reconciliation
  -> Final QA
  -> 两份可编辑 PPTX
```

### 4.1 共享核心

共享核心只负责与风格无关的能力：

- 原稿内容和素材提取。
- 研究级事实归一化。
- 原稿页码与内容追踪。
- 数字、治疗名称、时间点和引用验证。
- 运行目录、状态和错误报告。
- 最终文本回填与事实校准。
- PPTX 编辑性、完整性和渲染检查。

### 4.2 风格适配层

每个 Skill 分别维护：

- 内容画像。
- 可信参考页清单。
- 页面类型与叙事结构。
- 标题和正文写作规则。
- 视觉设计画像。
- image-to-image 提示词策略。
- 风格专属黄金样例和验收规则。

### 4.3 外部回建能力

`image-to-editable-ppt` 和 `editppt` 作为外部依赖使用，不在本项目复制或分叉其底层实现。

两个 Skill 只负责：

- 按约定准备逐页图片和运行目录。
- 调用回建流程。
- 读取页面 manifest 和验证结果。
- 使用已批准内容稿校准回建后的文本对象。
- 汇总最终 PPTX 和 QA 报告。

## 5. 参考风格文档拆解

参考文件夹不能直接作为一个模糊的“风格提示”。在内容改写前，必须先把每份参考 PPT 拆解成可检查、可复用的结构化风格资产。风格1和风格2分别执行同一套拆解流程，但独立形成分析结果。

### 5.1 第一步：参考文件预处理

对每份参考 PPT 建立 deck 级清单：

- 文件名、页数、画布比例和主题信息。
- 母版、版式、字体、颜色和媒体资源数量。
- 每页渲染图和整套 contact sheet。
- 原生文字、表格、图表、图片和组合对象清单。
- Office 锁文件、空白页、重复页和明显未完成页标记。

该步骤只描述参考文件真实状态，不提前判断哪些页面应被复用。

### 5.2 第二步：逐页结构拆解

每一页生成 slide catalog，至少记录：

- 页面角色：封面、总览、目录、章节、研究背景、研究设计、基线、疗效、安全性、结论、总结或讨论等。
- 叙事位置：该页在整套报告中承接什么上文、导向什么下文。
- 核心任务：该页希望读者记住什么。
- 标题语法：描述型、问题型、结论型、数据型或行动型。
- 正文结构：段落、要点、卡片、表格、图表、论文截图或混合结构。
- 信息密度：文字量、独立结论数、图表数和引用数。
- 视觉结构：栅格、留白、标题区、内容区、页脚区和主要对齐线。
- 视觉元素：字体层级、颜色、边框、底纹、装饰图形、图标和图片处理方式。
- 可复用部件：标题条、数据卡、研究流程、图表容器、结论框、页脚等。
- 质量等级、判断理由和分析置信度。

### 5.3 第三步：参考质量分级

参考页不采用简单的“全部学习”或“全部排除”，而是分级管理：

- A 级：内容和视觉均完整，可作为整页范本。
- B 级：整页不完整，但部分结构、部件或写法可复用。
- C 级：空白页、重复页、编辑指令页、明显错误页，只保留为反例。

类似“换模板”“加一个”“结果描述”等文字不会进入内容画像，但该页中仍然成熟的视觉部件可以在 B 级目录中单独保留。质量等级允许后续根据人工评审调整，不在代码中写死页码。

### 5.4 第四步：内容风格拆解

内容风格分析与视觉分析分开进行，重点提炼：

- 整套报告如何分章和推进故事。
- 单项研究通常如何展开，哪些环节会合并或拆分。
- 标题如何从研究事实形成结论。
- 背景、设计、数据、临床意义和局限分别占多大权重。
- 数据密集页和解读页如何交替。
- 总结页如何收束多项研究。
- 使用哪些证据强度词，如何表达不确定性。
- 页面数量如何随研究复杂度、图表数量和受众需求变化。

参考 PPT 中的医学事实只用于理解写法，不得混入目标原稿的 Evidence Ledger。

### 5.5 第五步：视觉系统拆解

视觉拆解应形成可执行设计参数，而不是只提取颜色：

- 页面尺寸与安全区。
- 栅格、边距、对齐线和常用内容宽度。
- 标题、副标题、正文、注释和页脚的字体层级。
- 主色、辅助色、中性色和强调色的使用场景。
- 封面、目录、章节、表格、图表、研究设计和总结等页面族。
- 每个页面族的组件组成、密度范围和可变区域。
- 图片裁切、论文截图、图表、表格和装饰元素的处理规则。
- 允许变化的部分与必须保持统一的视觉特征。

### 5.6 第六步：形成动态风格画像

每个风格最终形成两层规则：

- 稳定特征：跨多数高质量参考页持续出现，用于保持风格识别度。
- 可变策略：根据研究复杂度、素材类型、受众和页面任务动态选择。

风格画像不预设固定页数，也不要求每项研究使用相同页面数量。它提供候选页面族、内容节奏和选择条件，由后续 Page Planner 根据当前原稿动态组合。

### 5.7 拆解产物

每种风格至少产生：

- `deck-inventory.json`：参考文件级清单。
- `slide-catalog.json`：逐页内容与视觉结构。
- `reference-quality-report.md`：A/B/C 级页面及理由。
- `content-patterns.md`：叙事、标题、证据和解读规律。
- `visual-system.md`：设计系统和页面族规则。
- `component-library.json`：可复用组件及适用条件。
- `page-type-contact-sheets/`：按页面类型组织的视觉对照图。
- `anti-patterns.md`：明确不应学习的内容和视觉问题。

这些文件是两个 Skill 的正式输入资产，并进入版本控制。

## 6. 事实底稿设计

### 6.1 Evidence Ledger

Evidence Ledger 是两个 Skill 的共同事实来源。每项研究至少包含：

- `study_id`：稳定研究编号。
- `study_name`：标准研究名称。
- `source_slides`：对应原稿页码。
- `topic`：疾病和治疗场景。
- `population`：研究人群。
- `design`：研究类型、分组、周期和终点。
- `interventions`：治疗方案和剂量信息。
- `efficacy_claims`：疗效事实及其原稿位置。
- `safety_claims`：安全性事实及其原稿位置。
- `numbers`：HR、CI、P 值、比例、时间点和样本量。
- `limitations`：随访长度、证据等级和结论边界。
- `citations`：原稿引用和论文截图来源。
- `assets`：图表、表格、图片和论文截图。
- `allowed_inferences`：允许的归纳表达。
- `forbidden_inferences`：不得升级的结论。

### 6.2 事实类型

内容中的每个主要陈述必须标记为以下类型之一：

- `source_fact`：原稿明确提供的事实。
- `derived_summary`：由同一研究多条事实归纳出的总结。
- `editorial_bridge`：用于连接章节或解释叙事关系的编辑性表达。

模型不得把 `derived_summary` 或 `editorial_bridge` 写成新的临床证据。

### 6.3 提取原则

- 标题识别不能只依赖最大字号或第一个文本框。
- 表格、组合对象、图片和图表必须分别计数并保留页面坐标。
- 原稿文字需要保留段落、换行和单位。
- OCR 结果只能作为提示，不能覆盖 PPTX 中可直接读取的原生文字。
- 页面分类必须允许低置信度和人工复核，不得强制归入错误类别。

## 7. 动态页面规划

页面数量和拆分方式是规划结果，不是提前写死的参数。两个 Skill 共享 Page Planner，但使用各自的内容画像和页面族。

Page Planner 综合以下因素决定页数：

- 研究数量及每项研究的证据复杂度。
- 独立结论数量和结论之间的依赖关系。
- 需要保留的图表、表格、论文截图和引用数量。
- 目标受众、汇报时长和可读性要求。
- 参考风格常见的信息密度、页面节奏和页面族。
- 是否存在需要单独说明的安全性、局限或临床解读。

动态规划遵循三条约束：

1. 不因追求固定页数丢失改变结论方向的证据。
2. 不把多个无关核心任务强塞到同一页。
3. 不为模仿参考页数而制造空页、重复页或没有来源的内容。

Page Planner 输出 `page-plan.json`，每页记录页面任务、内容来源、所选页面族、拆分或合并理由和预计信息密度。风格1、风格2参考文件及现有不同页数的实验都只作为比较样本，不作为页数目标。

## 8. 风格1 Skill 内容设计

### 8.1 定位

风格1是医学会议型长报告：研究链条完整、信息密度高、保留关键图表，并使用结论型标题传达临床判断。

### 8.2 推荐结构

风格1通常适合医学会议型长报告，但具体页数由 Page Planner 决定。推荐叙事模块包括：

1. 封面。
2. 主题化总览。
3. 高危初治 DLBCL 章节。
4. 老年或脆弱 DLBCL 章节。
5. MZL/FL 章节。
6. 六项研究按各自证据复杂度组合背景、设计、结果、安全性和结论模块。
7. 章节小结。
8. 全篇趋势总结。
9. 结束页。

### 8.3 内容规则

- 研究顺序可以围绕治疗场景调整。
- 可以合并重复的背景、结果或安全性页。
- 关键疗效曲线、基线表、安全性表、MRD 结果和引用不得无理由删除。
- 标题优先表达本页结论，不使用连续重复的“研究结果”“安全性”等空标题。
- 语言采用克制、准确的医学部汇报口吻。
- 使用“显示”“提示”“可能”“仍需随访”等词控制证据强度。
- 早期单臂数据不得写成确证性结论。
- 研究小结必须同时包含获益、风险和证据边界。

### 8.4 可信参考目录

风格1三个参考文件先按第 5 节建立 A/B/C 级参考目录：

- 排除空白页。
- 排除“换模板”“加一个”“结果描述”等编辑指令页。
- 排除内容未完成或结构明显错误的页面。
- 按封面、目录、章节、研究设计、表格、图表、安全性、总结等类型各选可信样例。

内容画像和整页视觉范本优先使用 A 级页面；B 级页面只复用已明确标记的局部结构或部件。

## 9. 风格2 Skill 内容设计

### 9.1 定位

风格2是医学速递简报：页数相对精炼、信息清晰，常使用“研究证据 + 临床解读”的内容节奏，但不强制每项研究固定为两页。

### 9.2 推荐结构

推荐模块包括：

1. 封面。
2. 全篇总览。
3. 六项研究各自需要的证据模块和临床解读模块。
4. 总结或结束模块。

简单研究可以把证据与解读合并在一页；复杂研究可以拆成多页呈现研究设计、疗效、安全性或局限。Page Planner 根据素材和信息密度决定组合，不得通过虚构内容填满页面。

### 9.3 研究证据模块

研究证据模块按素材需要包含：

- 中英文研究名称或标准研究名称。
- 一句结论型标题。
- 研究目的。
- 研究设计和人群。
- 关键疗效或安全性结果。
- 主要图表或表格。
- 研究原始结论和引用。

### 9.4 临床解读模块

临床解读模块可以独立成页，也可以在信息量适合时与证据模块组合，内容包括：

- 核心判断。
- 关键证据。
- 临床意义。
- 创新性。
- 证据局限。
- 下一步需要验证的问题。

### 9.5 内容规则

- 风格2不默认沿用原稿页数或逐页改标题；如果动态规划认为保留某些原始页面最合适，应在 `page-plan.json` 中说明理由。
- 每项研究优先围绕一个主要临床问题组织；当疗效、安全性或适用人群构成相对独立的问题时，可以分别展开。
- 解读页必须明确区分研究结果与编辑性判断。
- 个案、单臂研究和 Meta 分析必须标明证据等级和局限。
- 不得因简化篇幅而省略影响结论方向的安全性信息。

## 10. 内容审核流程

内容阶段先于所有图片生成。每个 Skill 先产出 Markdown 内容稿和追踪清单，不直接修改 PPT。

### 10.1 第一轮试金石

使用 frontMIND 作为首个黄金样例：

- 风格1：覆盖研究引入、设计、主要结果、安全性和结论等必要模块，页数由试金石的 Page Planner 决定。
- 风格2：同时展示研究证据和临床解读两种内容任务，可以组合或拆分，页数由信息密度决定。

该样例必须先通过事实和文风检查，再扩展到其余五项研究。

### 10.2 内容验收

- 所有数字能追溯到原稿页码。
- 治疗名称、剂量、样本量、时间点、HR、CI 和 P 值准确。
- 不跨研究混用数据。
- 不遗漏改变结论方向的安全性信息。
- 结论强度与研究设计匹配。
- 风格1和风格2的结构与语气存在明确差异。
- 每页均有确定的页面任务、标题、正文和保留素材。

## 11. PPT 与图片流水线

### 11.1 中间原生 PPT

内容稿通过后，先生成中间原生 PPTX：

- 文字、表格和基本图形均为可编辑对象。
- 原始图表和论文截图以独立图片保存。
- 每个文本对象携带稳定内容 ID，供最终回填。
- 每页记录风格、页面类型、研究编号和原稿来源。

中间 PPT 的目的不是最终视觉交付，而是锁定内容、页序和素材。

### 11.2 逐页视觉重绘

- 将中间 PPT 渲染为逐页图片。
- 根据页面类型选择对应可信参考图。
- 使用风格专属提示词进行 image-to-image 重绘。
- 要求保留页面核心信息层级、图表含义和内容区域。
- 视觉阶段不得新增、删除或改写医学事实。
- 每页保留生成参数、输入图、参考图和输出图。

### 11.3 可编辑回建

- 使用 `image-to-editable-ppt` 按页回建。
- 标题、正文、标签和基础图形必须转换为可编辑对象。
- 复杂图表、论文截图、医学插图和装饰背景允许保留为图片。
- 不允许把整页图片作为唯一对象冒充可编辑结果。
- 页面验证失败时只重做失败页，不重新生成整套 deck。

### 11.4 最终文字校准

图片生成和 OCR 不能作为最终文字真相源。回建后必须：

- 依据稳定内容 ID，将已批准内容稿写回对应文本对象。
- 对比 Evidence Ledger 检查数字和术语。
- 检查文字回填后是否溢出或遮挡。
- 无法可靠匹配的文本对象标记为失败，进入人工复核，不能静默跳过。

## 12. 错误处理

### 12.1 提取错误

遇到无法识别的组合对象、标题或表格时：

- 保留原始对象快照。
- 将页面标记为 `needs_review`。
- 不使用低置信度结果覆盖原文。

### 12.2 内容冲突

同一数字或结论在不同页面不一致时：

- 记录所有来源页。
- 暂停该项陈述的风格改写。
- 在内容报告中列出冲突，不自行选择更有利的数字。

### 12.3 视觉生成漂移

出现文字改变、图表含义改变、关键素材丢失或风格失真时：

- 页面验证失败。
- 保留失败产物和原因。
- 仅重新生成该页。

### 12.4 回建失败

出现整页扁平化、文本缺失、对象越界或 manifest 不完整时：

- 页面不得进入最终合并。
- 输出明确失败原因和缺失文件。
- 修复后重新执行页面构建与验证。

### 12.5 原始文件保护

- 所有输出写入独立 run 目录。
- 不覆盖输入文件。
- Office 临时锁文件不作为有效输入。
- 密钥、Token 和认证文件不写入项目或运行报告。

## 13. 测试与验收

### 13.1 单元测试

- PPTX 原生文本、表格、图片和组合对象提取。
- 标题候选评分与低置信度处理。
- Evidence Ledger schema 验证。
- 数字、百分比、HR、CI、P 值和单位比对。
- 内容 ID 与文本回填匹配。
- 运行 manifest 状态转换。

### 13.2 黄金样例测试

frontMIND 同时作为两种风格的内容黄金样例，固定保存：

- 原稿事实底稿。
- 风格1内容稿及其动态页面规划。
- 风格2内容稿及其动态页面规划。
- 关键页面预览。
- 最终可编辑对象统计。

后续修改不能造成数字变化、事实遗漏或风格结构退化。

### 13.3 集成测试

- 从 47 页原稿生成完整 Evidence Ledger。
- 生成两套全量内容稿。
- 每种风格选择足以覆盖主要页面族的代表页面完成视觉和回建小样，数量由参考拆解和动态页面规划决定。
- 全量运行后验证两份 PPTX 的页数、对象、文字和素材。
- 在 PowerPoint 或兼容渲染器中重新渲染并检查差异。

### 13.4 最终验收标准

- 六项研究全部保留。
- 关键数字、治疗名称、时间点和引用与事实底稿一致。
- 风格1具备完整医学会议叙事，实际页数与 `page-plan.json` 一致且拆分理由可解释。
- 风格2形成清晰的研究证据与临床解读节奏，实际页数与 `page-plan.json` 一致且不存在机械压缩或扩页。
- 两份输出在内容结构和视觉上均有明显区分。
- 所有可见标题和正文可编辑。
- 复杂图表可为图片，但不得丢失或改变含义。
- 无整页单图冒充可编辑页面。
- 页面无文字溢出、对象遮挡和错误裁切。
- 任意主要结论可以追溯到原稿页码。
- 从干净输入目录可以重新运行并复现最终文件与报告。
